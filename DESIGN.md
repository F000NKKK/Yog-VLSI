# Yog VLSI — Design Document

> **Very Large Scale Integration** — проектирование, fabrication и деплой редстоун-микросхем с Rust-ускоренной симуляцией.

## 1. Обзор

Мод добавляет три ключевых блока: **VLSI Workbench** (верстак), **Microchip** (микросхема, 6 тиров), **ALU** (арифметико-логическое устройство, тоже 6 тиров), а также **аналоговые и цифровые кабели** для соединения ALU с внешним миром. Игрок проектирует редстоун-схему в виртуальном мире, «печатает» её на микросхему, вставляет микросхему в ALU — и получает сверхбыструю симуляцию своей логики в реальном мире.

Вся симуляция редстоуна выполняется нативным Rust VM — это даёт скорость до 40 тиков/с (2× vanilla) на Netherite-чипе.

## 2. Microchip (микросхема)

### 2.1 Тиры

| Тир | Материал | Шагов за тик (до) | Размер мира |
|-----|----------|-------------------|-------------|
| Wood | Дерево | 8 | 16×16×16 |
| Stone | Камень | 16 | 32×32×32 |
| Gold | Золото | 32 | 64×64×64 |
| Iron | Железо | 48 | 64×64×64 |
| Diamond | Алмаз | 64 | 128×128×128 |
| Netherite | Незерит | 128 | 256×256×256 |

Чип отвечает на входы в тот же серверный тик: каждый тик он шагает, пока схема не успокоится, но не больше бюджета тира (NOT — 2 шага, ≈1.5 мкс). Бюджет решает, насколько глубокая схема успевает за тик и с какой скоростью бегут часы внутри.

- Чем выше тир — тем больше виртуальный мир и быстрее симуляция.
- Каждый чип имеет уникальный UUID.
- Чип хранит метаданные в NBT (ChipMeta): ID, тир, имя, список портов.
- Схема (CircuitData) хранится на сервере через Storage API (отдельно от NBT, т.к. для чипа 256×256 это десятки тысяч блоков).

### 2.2 Порты

Порты — это ноды чипа, через которые он взаимодействует с внешним миром. В отличие от физических блоков на границе мира, порты **не привязаны к конкретным координатам** — они настраиваются в UI и существуют как логические точки подключения.

В виртуальном мире (редакторе) игрок размещает блоки `yog-vlsi:port` с NBT `{mode: "input"|"output"|"bidirectional"}` в любом месте сетки. При сохранении схемы эти блоки регистрируются как порты чипа.

```
Порт {
    label: "A0" | "CLK" | "Q" | ...
    dir:   Input | Output | Bidirectional
    pos:   (x, y, z)  — позиция внутри виртуального мира
}
```

Внутри VM каждый порт — это `Cell` с `BlockType::Port(mode)`, находящийся в конкретной ячейке грида. Сигнал на input-порту задаётся извне (ALU), сигнал с output-порта читается наружу.

Количество портов не ограничено — ограничена только сетка чипа.

### 2.3 Designs vs Fabricated Chips

Система разделяет **проект схемы** (Design) и **напечатанный чип** (Fabricated Chip):

**Design (чертёж):**
- Хранится на сервере для каждого игрока: `yog-data/yog-vlsi/player/<uuid>/designs/<design_id>.json`.
- Игрок может создавать, редактировать и удалять свои чертежи.
- Чертежи **доступны с любого верстака** — не привязаны к конкретному блоку. Игрок подходит к любому верстаку и видит все свои сохранённые схемы.
- Чертежи можно редактировать: зайти в виртуальный мир, изменить схему, сохранить.

**Fabricated Chip (напечатанный чип):**
- Получается при fabrication чертежа на верстаке (трата ресурсов).
- **Нельзя изменить или перепечатать.** Чип — неизменяемый физический предмет.
- Нельзя скопировать напечатанный чип обратно в чертёж.
- Если нужна другая версия — редактируй чертёж и печатай новый чип.

### 2.4 Blueprints (чертежи как предмет)

Игроки могут делиться схемами через предмет **Blueprint**:

- В GUI верстака есть кнопка «Export Blueprint» — создаёт физический предмет `yog-vlsi:blueprint` с NBT, содержащим CircuitData.
- Blueprint можно передать другому игроку.
- Другой игрок кладёт Blueprint в верстак → кнопка «Import» → схема копируется в его личную библиотеку чертежей.
- Blueprint **не тратится** при импорте (можно импортировать много раз).
- Blueprint нельзя использовать для fabrication напрямую — только для импорта в библиотеку.

Крафт пустого Blueprint (для записи):
```
P P P
P I P
P P P

P = paper
I = iron_ingot
```
Даёт 1 Blueprint. При экспорте из верстака пустой Blueprint заполняется данными схемы.

## 3. VLSI Workbench (верстак)

Верстак — центральный блок для работы с чипами. Игрок взаимодействует с ним через GUI, который показывает:
- **Библиотеку чертежей** — все сохранённые схемы игрока, доступные с любого верстака.
- **Слот для чипа** — для fabrication (печати).
- **Ресурсное хранилище** — пополняемое (MFU-стиль).
- **Слот для Blueprint** — для импорта/экспорта схем.

### 3.1 Крафт

```
I S I
S C S
I R I

I = iron_ingot
S = smooth_stone
C = crafting_table
R = redstone_block
```

### 3.2 Ресурсная система (Resource Ammo)

Верстак хранит ресурсы по принципу «краски в MFU»:
- Нет лимита на хранение.
- Игрок пополняет ресурсы, кидая предметы в верстак.
- Ресурсы трекаются как `HashMap<item_id, quantity>`.
- Персистентность: Storage API, ключ = позиция блока.

### 3.3 Fabrication (печать чипа)

Стоимость печати = **1/8 от vanilla-рецепта** каждого блока в схеме (размеры маленькие), округляется вверх один раз — за весь чип.

Вложенные АЛУ: блок АЛУ считается по своему рецепту (4 материала тира, 4 меди, повторитель, центральный блок), а схемы чипов в нём — ещё по 1/8 за каждый уровень вложенности (чип в АЛУ в схеме — 1/64, глубже — 1/512; не глубже 4 уровней).

Пример:
- 8 редстоун-пыли → 1 редстоун
- 4 повторителя (по 3 редстоуна, 3 камня, ¼ бревна) → 2 редстоуна, 2 камня, 1 дерево

Игрок выбирает чертёж из библиотеки, вставляет чистый чип нужного тира в слот. Ресурсы списываются из хранилища верстака. На выходе — **напечатанный чип** (Fabricated Chip) с NBT. Чип неизменяем, чертёж остаётся в библиотеке для дальнейшего редактирования.

### 3.4 Virtual World Editor (проектирование)

По нажатию кнопки «Design» (или «Edit» для существующего чертежа) в GUI верстака игрок телепортируется в creative-мир размером с тир чипа:
- Плоский мир из bedrock-пола.
- Игрок размещает **аналоговые блоки портов** (`yog-vlsi:port`) в любых клетках сетки. ПКМ по порту → меню: выбор режима (Input/Output/Bidirectional) и ввод имени (по умолчанию `Port N` / `Порт N`). Имя отображается floating text над блоком.
- Игрок строит редстоун-схему из любых доступных блоков, подключая редстоун к пинам портов.
- Все энтити (pearls, item frames, etc.) запрещены и чистятся при входе/выходе.
- Кнопка «Save» → схема сохраняется в личную библиотеку чертежей игрока (per-player, доступна с любого верстака). CircuitData записывается на сервер с координатами и подписями всех портов. Игрок возвращается в обычный мир.

## 4. ALU (арифметико-логическое устройство)

### 4.1 Тиры ALU

ALU тоже имеет 6 тиров, как и чипы. Тир ALU определяет:

| Тир | Материал | Макс. чипов внутри | Цифровых каналов / сторону |
|-----|----------|--------------------|----------------------------|
| Wood | Дерево | 2 | 8 |
| Stone | Камень | 3 | 16 |
| Gold | Золото | 4 | 24 |
| Iron | Железо | 5 | 32 |
| Diamond | Алмаз | 6 | 48 |
| Netherite | Незерит | 8 | 64 |

- Аналоговых портов всегда 6 (по одному на сторону), независимо от тира.
- Цифровые каналы = `цифровых_каналов × 4 цвета`. Netherite: 64×4 = 256 бит на сторону.

### 4.2 Крафты

#### ALU (базовый)

```
G C G
C R C
G D G

G = gold_ingot
C = copper_ingot
R = repeater
D = diamond
```

Крафт для более высоких тиров — замена центрального/угловых материалов на материал тира.

#### Analog Cable (аналоговый кабель)

```
R R R

R = redstone_dust
```

3 redstone dust → 3 analog cable. Прокладывается как редстоун-пыль.

#### Digital Cable (цифровой кабель)

```
G R G
R I R
G R G

G = gold_nugget
R = redstone_dust
I = iron_ingot
```

4 кабеля за крафт. Прокладывается как редстоун-пыль, может идти рядом с аналоговым без пересечений.

#### Redstone Port (блок адаптера редстоун ↔ ALU)

```
S S S
S R S
S S S

S = smooth_stone
R = redstone_dust
```

Ставится на любую сторону ALU. С одной стороны подключается аналоговый кабель, с другой — обычный редстоун.

### 4.3 Внешние порты ALU

ALU имеет **ровно 6 внешних портов** — по одному на каждой стороне блока (North, South, East, West, Up, Down). Эти порты — единственный интерфейс между ALU и внешним миром.

Внутренние порты чипов **не выходят наружу напрямую**. Игрок в UI связывает порты чипов с внешними портами ALU (или между собой — см. 4.5).

Редстоун **не взаимодействует с ALU напрямую**. Для подключения редстоуна нужен **Redstone Port** на стороне ALU и **Analog Cable**.

#### Типы внешних портов ALU

**Аналоговый (Redstone Port):**
- Один порт = один аналоговый сигнал 0–15.
- Подключается: `Редстоун → Redstone Port (блок) → Analog Cable → ALU`.
- Конфигурируется как Input или Output.

**Цифровой (шина):**
- Отдельного блока нет: сторона АЛУ, к которой подходит **Digital Cable**, становится **шиной** — в графе АЛУ появляется её узел («Шина E»), до 6 штук (по стороне).
- Шина — до 256 каналов (тир АЛУ видит `digital_channels × 4`: Wood 32 … Netherite 256), каждый — уровень 0–15; на одном канале у всех АЛУ одной сети — максимум того, что они пишут.
- У канала два пина: слева — что этот АЛУ пишет в шину, справа — что в ней. К ним цепляется что угодно: чипы, аналоговые стороны (Входы/Выходы), другие шины — так шина забирает на себя аналоговые порты.
- Узел показывает столько каналов, сколько игрок открыл: тянет полоску внизу узла вниз (как в LabVIEW).

### 4.4 Кабели

| Кабель | Передаёт | Пропускная способность | Соединяет |
|--------|----------|------------------------|-----------|
| **Analog Cable** | Аналоговый (0–15) | 1 сигнал | Redstone Port ALU ↔ внешний редстоун |
| **Digital Cable** | Цифровой (битовый) | До 256 бит | Digital Port ALU A ↔ Digital Port ALU B |

Оба кабеля — отдельные блоки. Цифровой и аналоговый кабель могут идти по одним и тем же координатам не пересекаясь (разные типы проводов).

### 4.5 Порты в виртуальном мире (чипа)

**Все порты внутри виртуального мира — аналоговые.** Это физические блоки `yog-vlsi:port`, которые игрок ставит в любой клетке сетки как обычный блок.

**Настройка порта (ПКМ по блоку):**
- Игрок ставит блок порта в виртуальном мире.
- ПКМ по блоку открывает простое меню:
  - **Режим:** Input / Output / Bidirectional.
  - **Имя:** текстовое поле. По умолчанию — `Port N` (EN) / `Порт N` (RU), где N — автоинкрементный номер. Игрок меняет на своё: `CLK`, `A0`, `Q`, `RESET` и т.д.
- Имя отображается floating text над блоком в виртуальном мире.
- В UI ALU это же имя показывается как метка пина (узла).

**Как работает порт в виртуальном мире:**
- **Input-порт** — «читает» редстоун-сигнал с подключённого провода (0–15). Это значение становится доступно в UI ALU как выходной пин данного порта. Его можно соединить с входом другого чипа или с внешним портом ALU.
- **Output-порт** — «пишет» редстоун-сигнал на подключённый провод. Значение приходит из UI ALU (от внешнего порта ALU или от выхода другого чипа) и выставляется как уровень сигнала 0–15 на этом блоке.
- **Bidirectional-порт** — может и читать, и писать.

При сохранении чипа все порты с их именами, режимами и координатами попадают в CircuitData.

### 4.6 UI: нодовый редактор ALU

GUI ALU открывается по ПКМ и представляет собой **flow-граф** в стиле ComfyUI / n8n / Blender Nodes:

```
┌─────────────────────────────────────────────────────┐
│  ALU (Netherite)  │  Чипов: 2/8  │  Каналов: 64    │
├──────────┬────────────────────────────┬─────────────┤
│          │                            │             │
│  Входы   │     [Чип "Adder"]          │  Выходы     │
│  ALU     │     ┌─A0──┐  ┌─SUM        │  ALU        │
│          │     │     │  │             │             │
│  ◉ N     │  IN─┤     ├──┤OUT       ──│── ● N       │
│          │     │     │  │             │             │
│  ◉ S     │     └─B0──┘  └─CARRY      │  ◉ S        │
│          │                            │             │
│  ◉ E     │     [Чип "Decoder"]        │  ◉ E        │
│          │     ┌─IN──┐  ┌─Q0         │             │
│  ◉ W     │  IN─┤     ├──┤OUT       ──│── ● W       │
│          │     └─────┘  └─Q1         │             │
│  ◉ U     │                            │  ◉ U        │
│          │                            │             │
│  ◉ D     │                            │  ◉ D        │
│          │                            │             │
├──────────┴────────────────────────────┴─────────────┤
│  [+ Добавить чип]  [Авто-линковка]  [Сохранить]     │
└─────────────────────────────────────────────────────┘
```

**Как устроен граф** (сервер — `board.rs`, экран — `alu.rs`):

- **Входы** (узел слева) — 6 сторон АЛУ как *источники*: уровень, который приходит по кабелю с этой стороны.
- **Выходы** (узел справа) — те же 6 сторон как *приёмники*: провод в `Выходы:N` выдаёт уровень в кабель стороны N. Сторона либо вход, либо выход: как только в `Выходы:N` заходит провод, `Входы:N` гаснет.
- **Чипы** (узлы в центре) — по одному на занятый слот: входные пины слева, выходные справа, двунаправленный — с обеих сторон. Имена пинов — имена портов из редактора.
- Провод идёт от источника (точка на правом краю) к приёмнику (точка на левом краю). Источник питает сколько угодно приёмников, приёмник принимает один провод.
  - чип → чип — внутренняя связь АЛУ;
  - Входы → чип — сигнал снаружи;
  - чип → Выходы — сигнал наружу;
  - Входы → Выходы — транзит.
- Если на кабеле стороны стоит **названный редстоун-порт**, его имя показывается у этой стороны в обоих узлах.
- Провода окрашены по уровню сигнала, у выходных пинов виден текущий уровень.

**Операции:**
- Потянуть от выходного пина к входному (или наоборот) → провод.
- Потянуть провод с его входного пина → перенести на другой пин; в пустоту → удалить.
- «Очистить связи» → удалить все провода.
- Потянуть чип за заголовок → переместить (позиция сохраняется).

### 4.7 Tick-обработчик

Каждый серверный тик (20/с), за один проход:
1. Redstone Port'ы-входы отдают редстоун в аналоговые кабели (сеть Pipes пересчитывается сразу).
2. АЛУ читает свои стороны (аналоговые кабели и шины) и выходы чипов, раздаёт всё по проводам графа на входы чипов.
3. Чипы успокаиваются: шагают, пока схема меняется, до бюджета своего тира.
4. Выходы чипов уходят по проводам на стороны (аналоговые кабели) и в каналы шин.
5. Redstone Port'ы-выходы выставляют редстоун из кабелей.

Сигнал от рычага до лампы через АЛУ проходит за один тик.

### 4.8 Установка чипов

Чипы — настоящие предметы в 8 слотах инвентаря АЛУ. Тир АЛУ питает первые `max_chips` слотов, чипы в остальных выключены (на графе — «выкл»). Вынул чип — его узел и провода пропадают с графа (провода вернутся, если вставить чип с теми же пинами).

### 4.9 АЛУ внутри схемы

АЛУ с чипами можно поставить в поле редактора, как любой блок. При сохранении чертежа он попадает в схему вместе с чипами в слотах и проводами своего графа (без шин: кабелей внутри чипа нет); при открытии чертежа в редакторе восстанавливается так же.

Внутри напечатанного чипа такой АЛУ — компонент VM: его шесть граней читают редстоун-мощность соседей и отдают на них уровни, как стороны настоящего АЛУ. Его чипы работают внутри него — каждый со скоростью **своего** тира: за серверный тик он делает не больше своих шагов, сколько бы ни сделала схема вокруг (Netherite в Netherite — та же скорость, Wood в Netherite — медленный Wood, хотя редстоун вокруг быстрый). Вложенность — до 4 уровней.

## 5. Rust Redstone VM

### 5.1 Архитектура

```
RedstoneVM {
    tier: Tier,
    width, height: u32,
    grid: Vec<Cell>,          // width × width × height
    updates: VecDeque<Pos>,   // очередь обновлений
    tick: u64,
}
```

Каждая ячейка:
```
Cell {
    block: BlockType,
    power: 0..15,
    strongly_powered: bool,
    weakly_powered: bool,
    repeater_timer: u8,
    torch_burnout: u8,
}
```

### 5.2 Алгоритм тика

1. **Reset** — сброс power у всех проводов, сброс weakly_powered.
2. **Process updates** — обработка очереди: факелы (инверсия), повторители (задержка), observer (2-тиковый импульс).
3. **Propagation (BFS)** — от всех источников питания (факелы, повторители, рычаги, кнопки, redstone_block, target, pressure plates, trapped_chest, detector_rail, I/O-порты) → BFS по redstone_wire с затуханием -1 за блок.
4. **Solid powering** — strong power от редстоун-компонентов в solid-блоки; weak power через соседние solid-блоки.
5. **Timers** — decrement repeater_timer, torch_burnout.

### 5.3 Поддерживаемые блоки

**Редстоун:** wire, torch, wall_torch, repeater, comparator, lever, stone_button, wood_button, stone_pressure_plate, wood_pressure_plate, light_weighted_pressure_plate, heavy_weighted_pressure_plate, observer, note_block, target, lamp, redstone_block.

**Solid/проводящие:** Solid (все обычные блоки), Glass (непроводящий), piston, sticky_piston.

**Контейнеры:** chest, trapped_chest, ender_chest, shulker_box, barrel, hopper, dropper, dispenser, furnace, blast_furnace, smoker, brewing_stand.
- Инвентари не симулируются, но блоки корректно проводят/блокируют редстоун.
- Trapped chest выдаёт power = количеству «зрителей» (упрощённо).

**Механика:** slime_block, honey_block, tnt, iron_door, wood_door, iron_trapdoor, wood_trapdoor, fence_gate, rail, powered_rail, detector_rail, activator_rail.

### 5.4 План развития VM

- **Comparator logic** — compare/subtract режимы, чтение контейнеров.
- **Observer detection** — детект block updates в VM.
- **Piston push/pull** — физика движения блоков.
- **Hopper/Dropper item transfer** — симуляция предметов.
- **Noteblock** — частота от питания.

## 6. Команды

Мод предоставляет набор команд для администрирования, отладки и творческого режима.

### 6.1 Команды игрока

| Команда | Описание |
|---------|----------|
| `/vlsi` | Открывает GUI-библиотеку чертежей (если игрок не рядом с верстаком) |
| `/vlsi library` | Показать список сохранённых чертежей |
| `/vlsi blueprint export <name>` | Экспортировать чертёж в Blueprint (требуется пустой Blueprint в руке) |
| `/vlsi blueprint import` | Импортировать Blueprint из руки в библиотеку |

### 6.2 Административные и debug-команды

| Команда | Описание |
|---------|----------|
| `/vlsi chip <tier>` | Выдать чистый чип указанного тира |
| `/vlsi test <tier>` | Создать чип с тестовой схемой (power source → wire → lamp) |
| `/vlsi info` | Показать детальную информацию о чипе в руке |
| `/vlsi vm step` | Выполнить один тик симуляции на чипе в руке и показать состояние портов |
| `/vlsi vm reset` | Сбросить VM-кэш всех ALU |
| `/vlsi alu list` | Показать все установленные чипы в целевом ALU |
